1. Overview & Navigation

The LVT SOP Builder is a browser-based tool for creating, managing, and exporting Standard Operating Procedures for manufacturing operations. Content is organized in a four-level hierarchy:

🏗️ LineProduction Line
→
🏭 StationSOP Document
→
📋 TaskStep Group
→
🔢 StepInstruction

Top Navigation Tabs

  • 🏗️ Lines — Primary workspace. Create lines, build stations, author all SOP content.
  • 📊 Line Balance — Analyze and compare cycle times across stations or tasks.

2. Lines

A Line represents a production line and groups stations together in order. The Line Name appears in every SOP header.

Creating a Line

  1. Click + New Line.
  2. Enter a Line Name — e.g. Powder Coat. This appears in all SOP PDF headers.
  3. Enter a Station Identifier — e.g. PWD-WIP. This becomes the prefix for all station numbers on this line.
  4. Optionally add a Description.
Auto-Numbering: Once a Station Identifier is set, every station added to the line receives an automatic Station No. — PWD-WIP-01, PWD-WIP-02, etc. Numbers reassign automatically when you reorder stations.

Line Actions (header bar buttons)

ButtonAction
+ StationCreate a new station and add it to this line
💾 SaveExport just this line as a .json file
📄 All PDFsExport a PDF for every station in this line
✕Delete the line (stations are not deleted, just unassigned)

Managing Stations in a Line

  • Drag the ⠿ handle to reorder stations. Station numbers update automatically.
  • Click Remove from line to detach a station without deleting it.
  • Use the Add existing station dropdown at the bottom to pull in a station that already exists in the project.

Tools & Equipment List

  • Click + Add Tool to add one tool (Name + optional Part/Model #).

Select text in the description field, then click B for bold or I for italic in the toolbar above the field. Formatting renders in both the preview and the PDF.

  • ↪ Move — move the step to any task in any station.
  • ✕ — delete the step.

6. Preview & PDF Export

Preview

Click 👁 Preview on any station to open a full-screen view that renders the SOP exactly as it will print — white 8.5×11 pages on a dark background.

The preview includes:

  • Cover page — Purpose, Safety Summary, Applicable Drawings, Tools & Equipment, Revision Log, Table of Contents, and Icon Legend.
  • One page per task — header, general notes, cycle time, tools/drawings used, and step table.
  • Continuation headers — when a task spans multiple pages, the task ID and description repeat at the top of each overflow page.
  • Footer on every physical page — Left: Company/Author · Center: Page X of Y · Right: SOP ID and Effective Date.

Exporting to PDF

  1. Click 📄 PDF on the station, or Print / Save PDF inside the Preview.
  2. In the print dialog, set Destination to Save as PDF.
  3. Confirm paper size is Letter (8.5×11) and layout is Portrait.
Color tip: In Chrome/Edge, enable "Background graphics" in print settings to preserve the teal header colors in the PDF.

7. Line Balance

Switch to the 📊 Line Balance tab to analyze cycle times and identify bottlenecks.

Scope Filter

  • All Stations — compares every station in the project.
  • Line: [dropdown] — filters to stations within one selected line.
  • Station: [dropdown] — drills into one station and shows a task-by-task breakdown.

Reading the Chart

  • Each bar = one station (or task in single-station mode).
  • The orange line = average cycle time (takt reference).
  • Red bars = stations more than 10% over the average — rebalancing candidates.

Click ⬇️ Export CSV to download the current view as a spreadsheet.

8. Saving & Loading

The SOP Builder offers three save methods. Every 💾 Save — at any level — automatically writes two files: a .json project file and a .csv backup, both with the same base name in the same folder.

⭐ Recommended Workflow — Open File Mode
  1. Store your .json project file in a shared folder — Google Drive, OneDrive, SharePoint, or a network drive
  2. Click 📂 Open File and navigate to that file
  3. Work normally — edit lines, stations, tasks, steps
  4. Click 💾 Save — writes both the .json and .csv back to the same location silently
  5. Team members open the same file from the shared folder to pick up where you left off

The Two Files — JSON and CSV

Every save produces two files with the same base name:

FilePurposeCan be opened with
Powder_Coat_2026-06-17.json Full project file — loads back into the SOP Builder with all data, images, structure, and settings intact SOP Builder (📂 Open File)
Powder_Coat_2026-06-17.csv Human-readable backup — every station, task, step, cycle time, safety icons, key points, and drawings in a flat spreadsheet. Readable without the app. Excel, Google Sheets, any spreadsheet app
Why two files? The .json is the working file — it contains everything including images. The .csv is your insurance policy — if the app were ever unavailable, all your SOP content is readable in a spreadsheet. Future versions of the app will support importing from CSV.

Method 1 — Open File Mode (Recommended)

Open a file once, save back to it as many times as you want — just like a traditional desktop app.

  1. Click 📂 Open File in the top nav bar.
  2. Navigate to your .json file — desktop, network drive, or Google Drive / OneDrive sync folder.
  3. The filename appears in the nav bar: 📄 Powder_Coat_2026-06-17.json ✕
  4. Make your changes.
  5. Click 💾 Save — writes both .json and .csv silently. Confirmation flashes: ✓ Saved → Powder_Coat_2026-06-17.json + .csv

First Save — What to Expect

The very first time you save after opening the app (or after clicking ✕ to close a file connection), two dialogs appear in sequence:

  1. Save As — JSON: Choose a folder and confirm the filename (e.g. Powder_Coat_2026-06-17.json)
  2. Save As — CSV: Immediately after, a second dialog opens pre-filled with the same base name as .csv — navigate to the same folder and click Save

After that, both files update silently on every subsequent 💾 Save — no more dialogs until you close the connection.

Works with Google Drive, OneDrive, SharePoint: Use their desktop sync app (Google Drive for Desktop, OneDrive sync) so files appear as a regular folder. Save writes back to the synced folder, which uploads to the cloud automatically.
Not simultaneous editing: One person at a time should have the file open and be saving. Treat it like a shared Excel file — coordinate with your team on who is editing.
To close the file connection: Click the ✕ next to the filename in the nav bar. Your data stays in the browser — you're just no longer linked to that file.

Save Scopes — Nav vs Line

ButtonWhat's savedDefault filename
Nav 💾 Save Everything — all lines and all stations All_Lines_YYYY-MM-DD
Line 💾 Save (on line header bar) That line and its stations only LineName_YYYY-MM-DD

Each scope remembers its own file handle independently — you can have the full project linked to one file and a single line linked to a separate file at the same time.

Method 2 — Export Save (Snapshots)

Creates a new dated file — useful for version snapshots before major changes, or distributing a copy to someone else.

Click ⬇️ Export Save to open the export dialog:

  • All Lines → saves as All_Lines_YYYY-MM-DD.json
  • Single Line → saves as LineName_YYYY-MM-DD.json

On Chrome/Edge a Save As dialog lets you choose the folder. On other browsers the file goes to the default Downloads folder.

Method 3 — Auto-Save (Safety Net Only)

The app automatically saves to browser localStorage on every change. Closing and reopening the tab restores your work automatically.

⚠️ Do not rely on auto-save as your primary save. localStorage is wiped if you clear browser cache, use a different browser, or switch computers. Always use Open File Mode as your primary workflow.

📥 Import Wizard (Selective)

Click 📥 Import to cherry-pick content from any save file — without replacing your current project.

  1. Pick file — supports both old format (stations only) and new format (lines + stations).
  2. Select items — check individual stations, tasks, or steps in a tree view. Selecting a full station includes all its tasks and steps automatically.
  3. Assign destinations — choose which line to add imported stations to. Assign orphan tasks/steps to existing stations and tasks.

Imported items receive new IDs so they never conflict with existing content.

9. Tips & Best Practices

Setup

  • Set the Station Identifier on a line before creating stations — every new station gets auto-numbered immediately (e.g. PWD-WIP-01).
  • Build your Tool List and Drawings on the station first, before writing tasks — they'll be available as dropdowns at every task and step.

Saving

  • Use Open File Mode as your primary workflow. Store the .json in Google Drive or a network folder, open it at the start of each session, and hit 💾 Save regularly — just like any other app. The .csv backup writes automatically every time.
  • On your first save, two dialogs open in sequence — one for the JSON and one for the CSV. Navigate both to the same folder so they stay together.
  • Use ⬇️ Export Save to create dated snapshots before major restructuring or before creating a new revision.
  • Never rely on browser auto-save as your only copy — it disappears with a cache clear.
  • Each save scope (nav vs line) remembers its own file independently. You can have the full project and a single line each linked to different files simultaneously.

Revisions

  • Use Revision A for initial builds. Only create new revisions (B, C…) when formally updating — the Windchill reminder in the dialog ensures uploads aren't missed.
  • The revision letter is editable in the dialog — you can skip from A to C, or go to AA if needed.

Rebalancing

  • Use ↪ Move Task or ↪ Move Step to rebalance rather than rebuilding — content, images, cycle times, and tool/drawing assignments all move with the item.
  • Use the 📊 Line Balance tab's Station scope to drill into a single station and see which tasks are the bottleneck within it.

Formatting & Content

  • The Bold/Italic toolbar on step descriptions works by selecting text first, then clicking B or I. Renders correctly in preview and PDF.
  • The Import Wizard is the best way to reuse content across lines or copy a station structure from one project file into another.
  • Insert a step between existing steps using the + button that appears in the gap between steps — no need to add at the bottom and drag up.
