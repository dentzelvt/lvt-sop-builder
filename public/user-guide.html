☰ Sidebar Navigator

The sidebar shows a collapsible tree of all Lines → Stations → Tasks. It is sticky — it stays visible as you scroll. Expanding the sidebar tree does not change the workspace; it is purely for navigation.

  • Click the ▶ chevron or line/station name to expand the tree
  • Click the → arrow button on a Line or Station to jump to it in the workspace (opens it and scrolls to it)
  • Click a Task row to jump directly to that task
  • Unassigned stations appear at the bottom with individual ✕ delete buttons and a Delete all option

Workspace Collapse Controls

Lines, stations, and tasks all start collapsed by default for a clean workspace.

  • ⊟ Collapse All — appears in the Lines header when any line is open; collapses everything
  • ⊟ Collapse Stations — appears inside each open line; collapses all stations in that line
  • Click any line or station header to toggle it open or closed
Browser refresh: The app auto-saves your workspace to the browser on every change. However, browser auto-save is not fully reliable across all configurations. The primary workflow is to use 💾 Save to write to a file — this is the only guaranteed way to keep your work.

2. Saving & The File Workflow

⭐ How LVT Uses the SOP Builder

Each line is saved to its own file, stored in a shared team location. Users load the lines they work on, make changes, and save back to the same files.

  1. Build your workspace — add all lines, stations, tasks, and steps
  2. Use each line's 💾 Save button to save it to its own file (Powder_Coat.json, MMS_Trailer.json, etc.)
  3. Store each file in the shared team folder (Google Drive, OneDrive, SharePoint)
  4. Next session: use 📥 Add Line from File to load the lines you need
  5. Make changes, save regularly with the line's 💾 Save

The Two Files — JSON and CSV

Every 💾 Save writes two files with the same base name:

FilePurposeOpens with
.jsonFull save file — all data, images, tools, drawings, revision log. Required to reopen in the builder.SOP Builder (📂 Open)
.csvComprehensive backup — every station, task, step, revision, tools, drawings in human-readable form. Used for recovery if the JSON is lost.Excel, Google Sheets, or ♻️ Restore from CSV

Nav 💾 Save (All Lines)

The 💾 Save button in the top nav saves all lines and stations in your workspace to a single file.

  1. Click 💾 Save
  2. First time: a Save As dialog opens — name it (e.g. All_Lines) and choose a location. A second dialog opens for the CSV — save in the same folder.
  3. After linking: all future saves are silent. The filename appears in the nav bar. The Save button shows a green border and ● indicator.
Disconnecting the nav file: Click ✕ next to the filename in the nav bar to unlink it. The next Save will prompt for a new location.

Line 💾 Save (Individual Lines)

Each line in your workspace has its own 💾 Save button in the line header. This saves only that line and its stations to its own file — the recommended workflow for team sharing.

  • First save: prompted for JSON filename, then CSV filename
  • After linking: a badge shows the linked filename next to the button — e.g. 💾 Save | Powder_Coat.json ✕
  • Click ✕ on the badge to unlink that line's file without affecting other lines

📂 Open (Load a Workspace File)

  1. Click 📂 Open in the nav bar
  2. Select a .json file — loads all lines and stations from it, replacing the current workspace
  3. A prompt asks if you want to also link the companion .csv — browse for it or skip

📥 Add Line from File

This is the primary way to bring individual lines into your workspace without replacing what you already have.

  1. Click 📥 Add Line from File (next to + New Line in the workspace)
  2. Select a .json file containing the line you want
  3. New lines are added automatically. If a line with the same name already exists, a conflict resolution modal appears — see Section 9.
  4. After the merge, a Link Files dialog appears — choose to use the existing file or create a new one for this line

More ▾ — Additional Save Options

OptionWhen to use
⬇️ Export SaveCreate a dated snapshot — choose All Lines or a Single Line. Good for version archives before major changes.
📥 Import StationsCherry-pick individual stations, tasks, or steps from any save file without replacing your workspace.
♻️ Restore from CSVRecover a full line from a .csv backup when the JSON is lost or corrupted.
📊 Download CSVDownload a CSV of all current station data (manual backup).
📄 All PDFsExport a PDF for every station in the workspace.

♻️ Restore from CSV

If a .json file is lost or corrupted, the companion .csv can fully restore the line.

  1. Click More ▾ → ♻️ Restore from CSV
  2. Browse for the .csv file
  3. A preview shows all stations found and their content — edit the restored line name if needed
  4. Click ♻️ Restore Line — the line is added to your workspace

The CSV backup captures: Station fields, ASM version, SOP revision, revision log (all entries), tools & equipment, applicable drawings, all tasks and steps with cycle times, key points, and safety icons.

Not recovered from CSV: Images (photos attached to steps or tasks). Only the JSON contains images. Always keep the JSON as the primary backup.

Session Reconnect

File handles cannot be saved across browser sessions (browser security limitation). When you reopen the builder after closing the browser, a Reconnect Files modal automatically appears for any lines that had files linked. It shows the expected filename and walks you through re-selecting each file — one click per file if your file manager remembers the location.

3. Lines

A Line represents a production line and groups stations together in order. The line name appears in every SOP PDF header and in the sidebar navigator.

Creating a Line

  1. Click + New Line
  2. Enter a Line Name — e.g. Powder Coat
  3. Enter a Station Identifier — e.g. PWD-WIP. This becomes the prefix for all station numbers in this line.
  4. Optionally add a description
Auto-numbering: Once a Station Identifier is set, every station added to the line receives an automatic Station No. — PWD-WIP-01, PWD-WIP-02, etc. Numbers update automatically when you reorder stations. Each station's number is still editable individually.

Line Header Controls

ButtonAction
+ StationCreate a new station and add it to this line
💾 Save | filename.json ✕Save this line to its own file. Badge shows linked filename. ✕ disconnects the link.
All PDFsExport a PDF for every station in this line
✕Delete the line (confirmation required). Station data is not deleted — stations become unassigned.

Managing Stations Within a Line

  • Drag the ⠿ handle to reorder stations — station numbers update automatically
  • Use the Add unassigned station dropdown at the bottom to pull in a station that exists in the workspace but is not yet in a line
  • Delete a station using its ✕ button (confirmation required — all tasks and steps are permanently deleted)
  • ⊟ Collapse Stations — folds all stations in this line back to headers only

🔄 Version Check on Open

When a line has a linked file and you click its header to expand it, the app silently checks whether the file has been updated since you last loaded it. If it has, a prompt appears:

  • 🔄 Reload from file — replaces this line's stations with the latest version from disk
  • Continue with my version — opens the line as-is
  • Cancel — leaves the line collapsed

Tools & Equipment

  • Click + Add Tool to add one tool with an optional Part/Model number
  • Click + Add Multiple to bulk-add — one tool per line. Use a pipe for part numbers: Battery Tester | BT-2000

  • Click ✕ on any entry to delete it. The last entry cannot be deleted.
  • Every revision dialog shows a ⚠️ Windchill upload reminder

7. Preview & PDF Export

Click 👁 Preview on any station to open a full-screen view exactly matching the printed output.

The SOP document includes:

  • Cover page — Purpose, Safety Summary, Applicable Drawings, Tools & Equipment, Revision Log, Table of Contents, Icon Legend
  • Task pages — header, general notes, estimated cycle time, tools/drawings referenced, and step table
  • Continuation headers — task ID and description repeat at the top of overflow pages
  • Footer on every page — Author · Page X of Y · SOP ID and Date
  • Drawings table — two drawings per row, using the full column width

Exporting to PDF

  1. Click 📄 PDF on the station header
  2. In the print dialog, set Destination to Save as PDF
  3. Paper size: Letter (8.5×11), layout: Portrait

The suggested PDF filename is auto-named from the SOP ID and station description — e.g. PWD-WIP-01.A_RACKING_LOADING.

Color tip: In Chrome/Edge, enable "Background graphics" in print settings to preserve the teal header colors in the PDF.

8. Line Balance & AI Analysis

Switch to the 📊 Line Balance tab to analyze cycle times and identify bottlenecks.

Scope & TAKT Controls

All controls are on a single toolbar row:

ControlDescription
○ All StationsCompare every station in the workspace
○ Line: [▾]Filter to stations within one selected line
○ Station: [▾]Drill into one station — shows task-by-task breakdown
⏱ TAKT: [____]Enter TAKT time as MM:SS (e.g. 1:30) or seconds (e.g. 90). Sets the reference line for the chart and table. Clear with ✕.

Reading the Chart

  • Each bar = one station (or task in single-station mode)
  • When TAKT is set: red line = TAKT, dashed orange = average. Red bars = over TAKT.
  • When no TAKT: orange line = average. Red bars = >10% over average.

Table — vs TAKT / vs Avg Column

Each row shows the cycle time delta vs the reference (TAKT if set, otherwise average). Green = under, red = over, with ▲/▼ indicators.

✨ AI Analysis

Click ✨ AI Analysis (next to Export CSV) to generate a structured analysis prompt from the current line balance data.

  1. The prompt is automatically copied to your clipboard
  2. Claude.ai opens in a new tab
  3. Paste the prompt to receive a full lean manufacturing analysis

The analysis covers: line efficiency %, bottleneck identification, underloaded stations, specific rebalancing recommendations, and priority actions.

LVT Line Balance Skill: Install the LVT_Line_Balance_SKILL.md skill file in Claude.ai (Settings → Skills) for analysis tuned to LVT's trailer assembly context, station naming conventions, and output format.

Export CSV

Click ⬇️ Export CSV to download the current scope as a spreadsheet for further analysis.

9. Collaboration & Multi-User

The SOP Builder uses a file-based coordination model — each line is owned as an individual file, stored in a shared location, and accessed by team members as needed.

The LVT model: Each production line has its own .json + .csv file pair stored in a shared team folder. Engineers load only the lines they're working on. No two people should edit the same line simultaneously.

⚠️ File Conflict Detection

When you click 💾 Save while a file is linked, the app reads the file's current savedAt timestamp from disk before writing. If the file was updated by someone else since you opened it, a warning modal blocks the save:

  • Shows your open time vs the file's last save time
  • 📥 Review file changes — opens the Merge Lines dialog to compare versions line by line
  • ⚠️ Overwrite anyway — discards the other person's changes
  • Cancel — closes without saving; coordinate first

🔄 Version Check When Opening a Line

Clicking a line header checks whether the linked file has been updated since you last loaded it. If it has, you are prompted to reload from the file or continue with your version.

📥 Add Line from File — Conflict Resolution

When importing a line that already exists in your workspace:

OptionWhat it does
Keep your versionDiscards the incoming file — keeps what you have
Use file versionReplaces your version with the file's version
Keep bothAdds the file as a new line named "Line (imported)" — nothing is lost

The modal shows timestamps for both versions with the newer one highlighted in green.

Link Files After Import

After importing a line, a Link Files dialog appears with two options:

  • 📂 Use existing files — navigate to the existing .json and .csv to authorize writes back to them
  • 💾 Create new files — save as a new file with a chosen name and location

After linking, the line's 💾 Save button writes back to those files silently.

Recommended Team Workflow

  1. Store each line's file pair in the shared team folder
  2. Use 📥 Add Line from File to load lines into your workspace at the start of a session
  3. When prompted, link to the existing files so saves write back to the shared location
  4. Make changes and save regularly with the line's 💾 Save
  5. If a conflict warning appears, use Review file changes rather than overwriting
  6. Coordinate with teammates when actively editing a shared line
One line per file: Giving each line its own file (not one file for everything) is the most team-friendly setup — it eliminates write conflicts between engineers working on different lines simultaneously.

10. Tips & Best Practices

Setup

  • Set the Station Identifier on a line before creating stations — every new station gets auto-numbered immediately
  • Build the Tool List and Drawings table on a station before writing tasks — they become available as dropdowns at every task and step
  • Use + Add Multiple on the tool list to paste an entire tool list at once

Saving

  • Save each line to its own file. Use the line's 💾 Save button, not the nav Save, for team workflows.
  • On first save, two dialogs open — JSON then CSV. Put both in the same shared folder.
  • Use ⬇️ Export Save for dated snapshots before major restructuring or before creating a formal new revision.
  • Do not rely on browser auto-save — it is not guaranteed across all browsers and configurations. Always save to a file.
  • Keep the .csv alongside the .json — it is the recovery backup if the JSON is lost.

Navigation

  • Use the ☰ Sidebar to jump between lines, stations, and tasks without scrolling
  • Expanding the sidebar tree does not open items in the workspace — use the → arrow to navigate
  • Use ⊟ Collapse All to quickly clean up the workspace after expanding multiple items

Content

  • Cycle time: enter seconds (90) or MM:SS (1:30) — both work in the same field
  • Bold/Italic: select text in the description field, then click B or I in the toolbar above it
  • Multiple images per step: click 📎 Add Image as many times as needed — each image has its own ✕
  • Insert between steps: use the + button that appears in the gap between existing steps
  • Move Task: use the "Move to…" dropdown in the task header to move an entire task to another station

Revisions

  • Rev A is pre-seeded — only add new revisions when formally updating a published SOP
  • The revision letter is editable — you can enter AA, B, C, etc.
  • The revision date is editable — click ✏️ on any entry to change it
  • Every revision dialog includes a Windchill upload reminder checkbox to ensure compliance

Line Balance

  • Always set a TAKT time before analyzing — without it, bars are compared to average only, which can mask problems
  • Use the Station scope to drill into a single station and identify which tasks are the bottleneck
  • Use ↪ Move Task to rebalance — all content, cycle times, and images move with the task
