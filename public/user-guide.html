1. Overview & Navigation

The LVT SOP Builder is a browser-based tool for creating, managing, and exporting Standard Operating Procedures for manufacturing operations. Content is organized in a four-level hierarchy:

🏗️ LineProduction Line
→
🏭 StationSOP Document
→
📋 TaskStep Group

Navigation Tabs

  • 🏗️ Lines — Primary workspace. Create lines, build stations, author all SOP content.
  • 📊 Line Balance — Analyze and compare cycle times across stations or tasks.

Linked File Display

When a file is linked via Open File, the nav bar shows the connected files as a pill:

📄 All_Lines_2026-06-24.json ✕ + 📊 All_Lines_2026-06-24.csv ✕

  • Click ✕ next to the JSON → disconnects both files
  • Click ✕ next to the CSV → disconnects only the CSV (JSON stays linked; next Save will prompt for a new CSV location)
Browser refresh: Your workspace data is preserved through a refresh via auto-save. However, file handle connections are lost — you'll need to click 📂 Open File again to re-link your file after a refresh.

2. Lines

A Line represents a production line and groups stations together in order. The Line Name appears in every SOP PDF header.

Creating a Line

  1. Click + New Line.
  2. Enter a Line Name — e.g. Powder Coat.
  3. Enter a Station Identifier — e.g. PWD-WIP. This becomes the prefix for auto-generated station numbers.
  4. Optionally add a Description.
Auto-Numbering: Once a Station Identifier is set, every station added to the line receives an automatic Station No. — PWD-WIP-01, PWD-WIP-02, etc. Numbers reassign automatically when you reorder stations. The Station No. on each station is still editable if you need to override it.

Line Header Bar Buttons

ButtonAction
+ StationCreate a new station and add it to this line
💾 SaveSave just this line to a file. When linked, shows the filename badge with a ✕ to disconnect.
📄 All PDFsExport a PDF for every station in this line
✕Delete the line (with confirmation). Station data is not deleted — stations become unassigned.

Line File Badge

When a line has a linked save file, a badge appears next to its 💾 Save button showing the filename and a ✕ to disconnect:

💾 Save | Powder_Coat_2026-06-24.json ✕

Click ✕ on the badge to unlink — the line stays in the workspace but the next Save will prompt for a new file location.

Managing Stations in a Line

  • Drag the ⠿ handle to reorder stations. Station numbers update automatically.
  • Use the Add existing station dropdown at the bottom to pull in a station that already exists in the project.
  • Delete a station using the ✕ button on its header (confirmation required).

📥 Add Line from File

The 📥 Add Line from File button (next to + New Line) lets you merge lines from a saved file into your current workspace without replacing anything. This is the recommended way to bring in work from another user's file.

  1. Click 📥 Add Line from File.
  2. Select a .json save file.
  3. New lines are added automatically.
  4. If a line with the same name already exists, a conflict resolution modal appears — see the Collaboration section for details.

🔄 Version Check on Open

When a line has a linked file and you click its header to expand it, the app silently checks whether the file has been updated since you last loaded it. If it has, a prompt appears:

  • 🔄 Reload from file — replaces the line's stations with the latest version from the file
  • Continue with my version — opens the line as-is (you are working from an older version)
  • Cancel — leaves the line collapsed
This check only happens when you intentionally open a line to edit it — not on every page load.

Tools & Equipment List

  • Click + Add Tool to add one tool (Name + optional Part/Model #).
  • Click + Add Multiple to bulk-add: one tool per line. Use a pipe for part numbers: Battery Tester | BT-2000

Revision Log

  • Rev A — Initial Release is pre-seeded on every new station.
  • Click + New Revision to add a new revision. The dialog prompts for revision letter (defaults to next letter, editable), date (defaults to today), Revised By (pre-filled from the station field), and a description.
  • Every revision dialog shows a ⚠️ Windchill upload reminder.
  • Click ✏️ on any entry to edit its description and Revised By. Editing requires confirming a Windchill checkbox.

5. Steps

Steps are individual instructions within a task. Click + Add Step, or click the + button between existing steps to insert one at a specific position.

Step Fields

FieldDescription
Step NumberOptional. Toggle with the "Step Numbers" checkbox on the task. The setting persists to the PDF.
IconsMulti-select safety/reference icons. See legend below.
Cycle TimeEnter as seconds (plain number, e.g. 90) or MM:SS (e.g. 1:30). Both are automatically converted and summed in MM:SS min format.
DescriptionMain step instruction. Supports bold and italic formatting.
Key Point / NOTEYellow-highlighted note line. Also supports bold/italic.
🔧 ToolsMulti-select from station tool list. Only shown if tools are defined on the station.
📐 DrawingsMulti-select from station drawings. Only shown if drawings are defined.
ImageUpload a single reference image.

Cycle Time Input

The cycle time field accepts two formats:

  • Plain number — interpreted as seconds. Enter 90 → stored as 1 min 30 sec → displays as 1:30 min
  • MM:SS — enter 1:30 → 1 minute 30 seconds → displays as 1:30 min

All task and station totals display in MM:SS min format.

Bold and Italic Formatting

Select text in the description or key point field, then click B (bold) or I (italic) in the toolbar above the field. Formatting renders correctly in both the preview and the PDF.

Safety Icons

⚠️ Warning 🔶 Caution 📝 Note 🦺 PPE Required ⚡ Electrical 🏋️ Heavy Lift 🔍 Inspect

Step Actions

  • ⠿ Drag handle — reorder steps.
  • ↑ / ↓ — move step up or down one position.
  • ↪ Move — move the step to any task in any station.
  • ✕ — delete the step (confirmation required).

6. Preview & PDF Export

Click 👁 Preview on any station to open a full-screen view rendering the SOP exactly as it will print.

The SOP includes:

  • Cover page — Purpose, Safety Summary, Drawings, Tools & Equipment, Revision Log, Table of Contents, and Icon Legend.
  • One page per task — header, general notes, cycle time, tools/drawings used, and step table.
  • Continuation headers — task ID and description repeat at the top of each overflow page.
  • Footer on every page — Left: Company/Author · Center: Page X of Y · Right: SOP ID and Date.

Exporting to PDF

  1. Click 📄 PDF on the station header.
  2. In the print dialog, set Destination to Save as PDF.
  3. Confirm paper size is Letter (8.5×11) and layout is Portrait.

The suggested PDF filename is auto-named from the SOP ID and station description — e.g. PWD-WIP-01.A_RACKING_LOADING.

Color tip: In Chrome/Edge, enable "Background graphics" in print settings to preserve the teal header colors in the PDF.

7. Line Balance

Switch to the 📊 Line Balance tab to analyze cycle times and identify bottlenecks.

Scope Filter

  • All Stations — compares every station in the project.
  • Line: [dropdown] — filters to stations within one selected line.
  • Station: [dropdown] — drills into one station and shows a task-by-task breakdown.

Reading the Chart

  • Each bar = one station (or task in single-station mode).
  • The orange line = average cycle time.
  • Red bars = more than 10% over average — rebalancing candidates.

Click ⬇️ Export CSV to download the current scope as a spreadsheet.

8. Saving & Loading

Every 💾 Save — at either scope — automatically writes two files: a .json project file and a .csv human-readable backup with the same base name.

⭐ Recommended Workflow — Open File Mode
  1. Store your .json file in a shared folder — Google Drive, OneDrive, SharePoint, or a network drive
  2. Click 📂 Open File and navigate to that file
  3. Work normally — edit lines, stations, tasks, steps
  4. Click 💾 Save — writes both .json and .csv back to the same location silently
  5. Team members open the same file from the shared folder to continue where you left off

The Two Files — JSON and CSV

FilePurposeOpens with
.jsonFull project file — all data, images, structure, settings intactSOP Builder (📂 Open File)
.csvHuman-readable backup — every station, task, step, cycle times, icons. Readable without the app.Excel, Google Sheets

Method 1 — Open File Mode

  1. Click 📂 Open File.
  2. Navigate to your .json file.
  3. A modal asks if you want to also link the companion .csv — click 📂 Browse for CSV file to link it, or Skip to set it on first save.
  4. The filename appears in the nav bar. Make changes.
  5. Click 💾 Save — writes both files silently. Flash confirms: ✓ Saved → filename.json + .csv
First save without a file linked: Two Save As dialogs open in sequence — first for the JSON, then for the CSV. Navigate both to the same folder. After that, all saves are silent.
Disconnecting files: Click ✕ next to the filename in the nav bar. The JSON and CSV each have their own ✕ so you can disconnect them independently.

Save Scopes

ButtonWhat's savedDefault filename
Nav 💾 SaveEverything — all lines and stationsAll_Lines_YYYY-MM-DD
Line 💾 SaveThat line and its stations onlyLineName_YYYY-MM-DD

Each scope has its own independent file link — you can have the full project linked to one file and a single line linked to a separate file simultaneously.

Method 2 — Export Save (Snapshots)

Click ⬇️ Export Save to create a new dated file. Choose All Lines or a Single Line. Use this for version snapshots before major changes or to distribute a copy.

Method 3 — Auto-Save (Safety Net Only)

The app saves to browser localStorage on every change. Refreshing or reopening the tab restores the workspace automatically.

⚠️ Do not rely on auto-save as your primary save. localStorage is wiped if you clear browser cache, use a different browser, or switch computers. File handle connections are also lost on refresh — re-open your file with 📂 Open File after refreshing.

📥 Import Wizard

Click 📥 Import to cherry-pick content from any save file without replacing your current project.

  1. Pick file — supports both old format (stations only) and new format (lines + stations).
  2. Select items — check individual stations, tasks, or steps. Selecting a full station includes all its tasks and steps automatically.
  3. Assign destinations — choose which line to add imported stations to. Assign orphan tasks/steps to existing stations and tasks.

9. Collaboration & Multi-User

The SOP Builder does not have real-time simultaneous editing (like Google Docs). Instead it uses a file-based coordination model — similar to a shared Excel file on a network drive. The tools below protect against accidental overwrites and make merging straightforward.

The basic rule: One person edits and saves at a time. The tools below tell you when someone else has saved changes and give you options to resolve conflicts before overwriting.

⚠️ File Conflict Detection (Save Protection)

When you click 💾 Save and the app is in Open File Mode, it reads the current file from disk before writing. If the file's savedAt timestamp is newer than when you opened it, a warning modal blocks the save:

  • Shows You opened it at: 2:00 PM vs File last saved at: 3:00 PM
  • 📥 Review file changes before saving — opens the Merge Lines dialog so you can compare your version against the file version line by line
  • ⚠️ Overwrite anyway — discards the other user's changes (use only if you are certain your version is correct)
  • Cancel — closes the modal without saving; coordinate with the other user first

🔄 Version Check When Opening a Line

When you click a line header to expand it and that line has a linked file, the app silently checks whether the file has been updated since you last loaded it. If it has:

  • 🔄 Reload from file — fetches the latest version and replaces this line's stations in your workspace
  • Continue with my version — opens the line as-is; you are working from an older version
  • Cancel — leaves the line collapsed

📥 Add Line from File (Merge)

When another user has saved a line you also have, use 📥 Add Line from File to bring in their version and compare:

OptionWhat it does
Keep your versionDiscards the file version — keeps what you have
Use file versionReplaces your version with the one from the file
Keep bothAdds the file version as a new line named "Line (imported)" — nothing is lost

The modal shows timestamps for both versions with the newer one highlighted in green, making it clear which is the latest.

Recommended Team Workflow

  1. Store the project file on a shared Google Drive / OneDrive / network folder
  2. Before starting work, click the line header — if a newer version exists, reload it first
  3. Make your changes, save regularly with 💾 Save
  4. If a conflict warning appears on save, use Review file changes rather than overwriting
  5. Communicate with teammates when you are actively editing a shared line
Per-line files: The most effective team setup is to give each line its own save file (using the line's 💾 Save button). User A owns Powder_Coat.json, User B owns Final_Assembly.json — no conflicts at all.

10. Tips & Best Practices

Setup

  • Set the Station Identifier on a line before creating stations — every new station gets auto-numbered immediately.
  • Build your Tool List and Drawings on the station before writing tasks — they become available as dropdowns at every task and step.

Saving

  • Use Open File Mode as your primary workflow. Open your .json from a shared folder at the start of each session and hit 💾 Save regularly. The CSV writes automatically every time.
  • On first save, two dialogs open — JSON then CSV. Put both in the same folder.
  • Use ⬇️ Export Save for dated snapshots before major restructuring or before creating a new formal revision.
  • For teams: give each line its own file to eliminate conflicts entirely.
  • Never rely on browser auto-save as your only copy.

Revisions

  • Use Revision A for initial builds. Only create new revisions when formally updating — the Windchill reminder ensures uploads aren't missed.
  • The revision letter is editable — you can skip to C or use AA if needed.

Rebalancing

  • Use ↪ Move Task or ↪ Move Step rather than rebuilding — all content, images, and cycle times move with the item.
  • Use the Line Balance Station scope to drill into a single station and find which tasks are the bottleneck.

Content

  • Cycle time: enter seconds (e.g. 90) or MM:SS (e.g. 1:30) — both formats work in the same field.
  • Bold/Italic: select text in the description, then click B or I in the toolbar.
  • Insert between steps: use the + button that appears in the gap between existing steps.
  • Import Wizard: the best way to reuse stations across lines or projects.
